# 本地构建与划词授权

本地试用时固定使用同一个安装位置和开发证书。临时目录、DerivedData 和已安装应用中的
多个副本容易混淆，旧的 ad-hoc 签名授权也不等于当前构建已获授权。

## 构建

在仓库根目录运行：

```bash
bash scripts/setup-team.sh
bash scripts/build-local-app.sh
```

需要 Xcode 和可用的 Apple Development 证书。第一条命令生成被 Git 忽略的本机签名配置；
第二条命令使用该身份为当前 Mac 的架构构建并验证 Release 应用，在结尾输出应用路径。
它跳过工程的全仓格式化与 lint 阶段，不改写其他源码；代码检查需单独运行。默认 Release 发布签名
配置保持不变。更换开发证书或改用发行证书可能需要重新授权。

## 安装与授权

1. 退出所有旧 EasyRead 副本，将新应用复制到用户的 `~/Applications/EasyRead.app`，后续更新
   也替换同一位置；不要从构建或临时目录另开一份。
2. 打开已安装的应用，使用划词翻译触发系统权限提示。
3. 在系统设置的隐私与安全性中，为这一份应用开启辅助功能（部分系统版本称为“设备控制和
   数据访问”）。若列表存在多个同名条目，移除失效条目并通过 `+` 选择刚安装的应用。
4. 授权后退出并重新打开 EasyRead，在 TextEdit 中选中英文，验证划词按钮和划词快捷键。

应用在创建菜单栏和全局事件监听前检查相同 bundle ID 的实例。再次打开时唤起已有实例；
崩溃后锁会由系统自动释放。Debug 与 Release 使用不同 bundle ID，权限也分别管理。

macOS 用代码签名的 designated requirement 识别更新后的应用，详见
[Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。
应用自身不能替用户授予系统权限。

## 划词后的阅读流程

1. 在「设置 → AI 翻译」选择服务商、接口地址和模型，保存 API Key，测试连接后开启 AI 阅读。
2. 选中文字并提交查询；原文和译文显示在同一面板，译文标题旁提供朗读、复制。
3. 「句子解析」展示划线片段和下方标签，宽窗口中逐项解释在右侧并排显示，窄窗口改为上下排版。
4. 「词典」查看本地词典结果；「其他译文」对照其他启用服务。AI 出错不阻止独立的词典查询。
5. 在 macOS「词典」中下载并启用词库后使用苹果词典；它查询词条，不负责整段翻译。

AI 默认关闭。开启后查询可自动生成阅读结果，并可能产生所选 API 服务的费用。上下文采集在
隐私设置中单独开启；只有成功取得的有限上下文才会附带发送。取消、关闭窗口或切换查询会
取消当前阅读请求。完整说明见[中文 README](../../../README_ZH.md)与[隐私说明](../../../PRIVACY.md)。
