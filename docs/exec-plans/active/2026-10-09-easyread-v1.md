## 风险与决策

- **本机无 Xcode**：`xcodebuild build/test` 无法运行。替代验证：`swift test`（EasyReadKit）、
  `swiftc -parse`（app 层改动文件语法检查）、`plutil -lint`（pbxproj/plist）、`jq`（xcstrings）、
  `bash -n`（脚本）。app 层编译验证延后到用户安装 Xcode，如实记录，不谎报。
- **pbxproj 手工编辑**（objectVersion 55 经典分组）：新增文件需手工同步
  PBXFileReference/PBXBuildFile/group/Sources phase；用 `plutil -lint` + 结构检查降低风险。
- **pbxproj 无编辑器验证**：保持改动模式化、最小化；diff 审查。
- **Key 存储**：上游 apiKey 存 UserDefaults（明文）。EasyRead 新增 KeychainStore，DeepSeek
  覆写 `apiKey` 读取；UI 写入走 Keychain 分支 + 非敏感镜像 key 驱动验证按钮（避免依赖
  Defaults 自定义 Bridge 的观察语义）。
- **服务收窄采用“隐藏不删除”**：从 `QueryServiceFactory.serviceRegistrations` 移除条目，
  服务类与 ServiceType 保留（GPL 共享代码），`defaultServiceTypeIDs` 同步改为
  [appleDictionary, deepSeek]，避免 setup() 断言。
- **更新通道**：上游 SUFeedURL/appcast、GitHub release 检查指向 tisfeng/Easydict，
  必须禁用/移除，防止 EasyRead 用户误升级为上游二进制；归属链接（issues/releases 页面）保留。
- **遥测**：`allowAnalytics` 默认 true → false；Firebase 配置加 plist 存在性守卫并从 target
  移除 GoogleService-Info.plist；Sentry 随 allowAnalytics 关闭。
- **模型名**：上游已是 `deepseek-v4-flash`/`deepseek-v4-pro`（2026-10 官方名），与 SPEC 提及的
  `deepseek-flash` 不同；采用上游现有名称（更新、集中管理于 DeepSeekModel enum），在文档记录差异。
